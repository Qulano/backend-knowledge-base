1. Big(O) - нотация которая позволяет определить как быстро устанет наш процессор и как быстро оперативная память забьется при работе с        огромным потоком даных

    O(1) - Постоянное время
    Аналогия: чтобы узнать сколько времени нужно всего лишь посмотреть на часы, внешние факторы никак не влияются на значение
    Пример: доступ по ключу с словаре dict[key] или проверка x in my_set

    O(N) - линейное время, движемся поэтапно
    Аналогия: ищем ключи по карманам в гардеробе, нужно будет проверить N-курток (10 круток - 10 проверок, 1000 курток - 1000 проверок)
    Пример: поиск элемента в списке x in my_list или цикл for item in items

    O(N^2) - Квадратичное время (исследуем попарно)
    Аналогия: Каждый гость на вечеринке жмет руку каждому гостю
    Пример: Вложенный цикл for внутри цикла for или поиск по списку внутри другого цикла, это самое ужасное что может произойти в работе программмы, нужно изначально все продумывать так, чтобы такого не случилось


2. Память и потоковая обработка

    Изначально есть проблема чтения файлов целиком при использваонии (read(), readlines(), pandas.read_csv()):
    Весь файл полностью загружается в оперативную память RAM разом
    При обработке файла на 25 ГБ на сервере с 4ГБ RAM операционная система активирует OOM KILLER (Out-of-Memory Killer)
    который принудительно убивает процесс Python с ошибкой SIGKILL.

    Инженерное решение:
    Построчное чтение через генераторы (for line in file / csv.reader).
    В памяти находится только одна строка, которую мы проверяем и очищаем и так далее (почти не занимает память)
    в таком случае рсход памяти у нас констатный равный O(1), скрипту все равно сколько весит файл, сервер будет работаь без проблем


3. Проверка дубликатов: Списки(list()) против Множеств(set())

    Ловушка списков(list.append)
    Проверка if id in seen_ids переберает все элементы этого списка (Цикл - сложность O(N)), так как мы проверяем каждую строку то мы приходим к вложенному циклу(Сложность - O(N^2)), На больних данных скрипт упадет

    Решение через множества (set.add)
    set реализован как хэш-таблица  
    провер if id in seen_ids в множестве работает O(1) - мгновенно, поэтому весь файл обрабатывается за линейное время O(N)

    Примечание, при размере большом размере файла множества просто захлебнуться (O(N)) поэтому есть два пути
    1. Жертвуем точность но выигрываем в скорости, исползуя ФИЛЬТР БЛУМА - супер легкая структура данных, которая занимает очень мало места в памяти и говорит: элемента ТОЧНО или ВОЗМОЖНО присутсвует.
    Аналогия: Охранник на входе в клуб с идеальной зрительной памятью на лица, но без блокнота.
    Если подошел незнакомец — охранник скажет: «Этого человека тут ТОЧНО НЕ БЫЛО» (100% гарантия, никаких ложных пропусков).
    Но из-за темноты он иногда может обознаться и сказать: «Хм, кажется, я тебя уже видел», хотя человек пришел впервые (небольшая погрешность, ложноположительное срабатывание).

    2. Добиваемся максимальной точности, но сильно проигрываем в скорости External Merge Sort - файл разбивается на маленькие куски, которые сортируются в памяти, сохраняются на диске, а потом опять объединяются
    Аналогия: У тебя на полу гора из 1 000 000 разбросанных карточек, а на маленьком столике помещается только 100 штук.
    Что ты делаешь? Берешь по 100 штук, раскладываешь по алфавиту на столике и складываешь аккуратными стопочками обратно на пол. А потом просто берешь верхние карточки из стопочек и объединяешь в одну идеальную линию.


4. Как устроена хэш-таблица

    Принцип работы: 
    Ключ передается в функцию hash() вычисляется число по этому числу процессор мгновенно обращается к конкретной ячейке памяти (вешалке
    гардеробе). Поиск происходит в 1 шаг без перебора элементов O(1).

    Неизменяемость ключей (Immutable):
    Ключом словаря или элементом множества могут быть только неизменяемые типы данных (str, int, tuple). 
    Список list положить нельзя, потому что если список изменится, его хэш изменится, и объект потеряется в памяти.

    Коллизия:
    Ситуация, когда два разных объекта случайно выдали одинаковый хэш. Python умеет разрешать такие конфликты внутри сам.

    Динамическое расширение:
    Когда хэш-таблица заполняется примерно на 2/3, Python автоматически выделяет новый кусок памяти побольше, чтобы поиск всегда оставался быстрым O(1).

7. B-tree индексы под капотом PostgreSQL

    Без индекса (Seq Scan - Sequential Scan):
    База данных честно перебирает каждою строчку на диске от первой до последней
    Сложности по времени O(N). На миллионах записей запросы висят секундами

    С B-Tree индексом (Index Scan):
    B-Tree (Balanced Tree - Сбалансированное дерево): Структура данных в виде разветвленного дерева.
    Принцип работы: Похож на игру "Угадай число": каждый шаг делит оставшиеся варианты пополам (больше/меньше).
    Среди 1 000 000 записей точное значение находится всего за  ~ 20 шагов
    Сложность по времени: O(logN) (логарифмическое время - практически мгновенно)
    Суперсила B-Tree: В отличие от хэша, умеет быстро искать диапазоны ("<", ">", "BETWEEN") и делать сортировку ("ORDER BY")

    Почему нельзя вешать индексы на каждую колонку (столбец)?
    1. Расход памяти: Каждый индекс это отдельная тяжелая структура на диске и в RAM.
    2. Замедление записи (`INSERT`, `UPDATE`, `DELETE`): При добавлении одной новой строки база обязана не просто записать её, но и перестроить ветки во ВСЕХ существующих индексах. Много индексов = медленная вставка данных.
    Правило инженера: Индекс создается только на колонки, по которым часто идет поиск (`WHERE`) или объединение (`JOIN`)


8. Тестирование CLI программ и паттерн AAA (PyTest)

    Проблема CLI программв тестах:
    Пограмма с циклом `while True` и функцией `input()` ждут ввода человека с клавиатуры. В автоматических тестах PyTest такой скрипт просто зависнет намертво.

    Два встроенных супер-инструмента PyTest:
    1. `monkeypatch` - подменяет стандартные функции Python. Мы подменяем системный `builtins.input` на заранее заготовленных список строк, чтобы программа брала данные автоматически 
    2. `capsys` - "видеокамера над терминалом". Перехватывает весь текст, выведенный через `print()`, чтобы в конце проверять его через `assert`


    Золотой стандарт индустрии: Паттерн AAA (Arrange - Act - Assert)
    Любой тест в мире строится по 3 фазаам:

    1. Arrage (Подготовка До)
        Готовим тестовые данные, подделываем ввод через `monkeypatch` или создаем тестовые записи в БД
    2. Act (Действие Во Время)
        Запускаем целевую функцию: вызываем `run_calculator` или `client.get()`.
    3. Assert (Проверка После)
        Сверяем полученный результат с ожиданиями c помощью команды `assert`

    Архитектурный вывод
    Код должен быть спроектирован так, чтобы его было легко тестировать. Бизнес-логику лучше выносить в чистые функции без `input()` и `print()`
    а цикл ввода делать лишь тонкой оболочкой


9. Транзакция и 4 суперсилы ACID (PostgreSQL)

    Что такое транзакция базе данных?

    Аналогия из жизни: отправляю деньги своему другу, на твоем счете они списываются а на его счете они прибавляются, что если вдруг сервер внезапно упадет, деньги списали и не перешли на другой счет, по итогу они просто улетели в пустоту, чтобы этого избежать требуется зафиксировать выполнение всех действий - транзакцию

    Транзакция - это контейнер, в который мы заворачиваем SQL команды.

    Работает по правилу "ВСЕ ИЛИ НИЧЕГО" (All-or-Nothing)

    Два исхода:
    `COMMIT` - все прошло успешно, запечатать и сохранить изменения в базу намертво
    `ROLLBACK` - произошла ошибка, удалить контейнер и откатить базу до исходного состояния


    Четыре суперсилы транзакции - ACID

    1. A - Atomicity (Атомарность):
    Суть: Транзакция неделима, как атом. Либо все, либо ничего
    Пример спасения: Скрипт вставляет в базу строки, вдруг попадается битая строка, база возвращается к исходному состоянию (ROLLBACK), в таблице БД не остается огрызков

    2. C - Consistency (Согласованность / Непротиворечивость):
    Суть: Нельзя нарушать правила базы данных
    Пример: БД никогда не даст сохранить заказ без существующего клиента, отрицательную цену или пустую строку там, где стоит ограничение
    NOT NULL

    3. I - Isolation (Изоляция):
    Суть: Одновременные операции тысячи пользователей не путают друг друга
    Защита от Race Condition (состояние гонки): Если два человека в одну минуты жмут "Купить" на последний товар на складе, база изолирует их процессы. Первый купит товар, а второму база ответит: "Товар закончился". Товар не продастся дважды

    4. D - Durability (Долговечность / Надежность):
    Суть: если БД ответила `COMMIT`, данные гарантированно записаны на жесткий диск (в специальный журнал WAL).
    Даже если через пару милисекунд сервер вырубит - после выключения данные не пропадут


10. Docker: Персистентность данных и Volumes (Тома)

    1. Проблема эфемерности контейнеров:

    Контейнер по умолчанию одноразовый. Все изменения пишутся во временной слой (writable layer)
    Если база данных PostgreSQL запущена без `volumes`, то при выполнении команды `docker compose down` контейнер уничтожается вместе со всеми данными, таблицами и индексами без возможности восстановления

    2. Что такое Docker Volume (Аналогия: Внешний SSD / Флешка)
    Контейнер это арендованный ноутбук 
    Volume - внешний диск, лежащий на сервере
    Мы пробрасываем провод (монтируем) внутреннюю папку базы данных (`/var/lib/postgresql/data`, где лежат таблицы и WAL-логи) на реальный диск хоста.

    3. Результат:
    База пишет данные напрямуб на сервер
    При `docker compose down` «ноутбук» утилизируется, но внешний диск с данными остается целым на хосте.
    При следующем `docker compose up` новый контейнер мгновенно подключается к существующему диску, и все данные на месте.


11. Высоконагруженный Data API: FastAPI, Redis, Alembic и метрики

    1. Асинхронность (Event Loop) и async/await:

    Аналогия с рестораном: 1 официант (1 ядро CPU / Event Loop) и повар (I/O: база данных, диск, сеть).
    официант отдает заказ на кухню `await` и будет обслуживать других клиентов, не простаивая в ожидании готовности блюда.
    Конкурентность без блокирования потока

    2. Connection pool (Пул соединений) в asyncpg:

    Создание соединений с нуля дорогое: TCP 3-Way Handshake + аутентификация + `fork()` отдельные процессы в PostgreSQL
    с выделением памяти.
    Пул соединений держит 10-20 уже открытых и авторизованных соединений (служебные такси). Запрос берет свободное соединение (`acquire`),
    быстро делает запрос и возвращает обратно (`release`). Задержка на подключение = 0 мс

    3. Redis и паттерн Cache-Aside (Кэш на обочине)

    Cache Hit: Нашли ключ в Redis отдали за 1-2 мс из RAM.
    Cache Miss: Данных нет тяжелый расчет в PostgreSQL сохранили в Redis в формате JSON c временем жизни (TTL)
    Зачем нужен TTL: экономия дорогой оперативной памяти и защита от протухания данных(Stale Data)

    4. Миграции баз данных (Alembic):

    Это Git для структуры таблиц. Исключает ручные правки на сервере.
    В PostgreSQL создается таблица `alembic_version`, где хранится текущий  хэш ревизии.
    Команды `alembic upgrade head`(накатить до последней) и `alembic downgrade`(безопасный откат).

    5. Метрики нагрузки (Locust):
    RPS (Requests Per Second): Сколько запросов в секунду бэкенд успевает полноценно обработать. В нашем проекте: 318 RPS
    Перцентили P95 / P99 против среднего (Average):
    Среднее время ответа врет (средняя температура по больнице), маскируя единичные зависшие запросы
    P95: 95% всех пользователей получили ответ быстрее этого порога (только 5% ждали дольше). Это главный ориентир в SLA и High-Load


12. Docker Network (DNS) и Логирование (Loguru)

    1. Docker Network и внутренний DNS
    Каждый контейнер полностью изолирован и имеет свой собственный `localhost` (127.0.0.1)
    FastAPI не может подключиться к базе через `localhost`, так как Postgres находится в другом изолированном контейнере
    Docker Compose автоматически создает общую подсеть и поднимает Embedded DNS Контейнеры находят друг друга по имени сервиса из файла YML (например, `postgres:5432`)

    2. Логирование через Loguru (почему не print()):
    Уровни критичности: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` позволяют фильтровать поток событий и настраивать алерты
    Контекст ошибки: автоматически сохраняет точно время с милисекундами, имя модуля, функции и номер строки
    Ротация и очистка (Rotation & Retention): предотвращает переполнение диска сервера (авто-нарезка логов по 10 МБ и удаление старых через N дней)


13. Объектно-оринентированное программирование (ООП) в Python

    1. Класс и объект (Формочка и Печенье):
    Класс (Class) Формочка. Определяет структуру поведения
    Объект (Instance) Конкретно печенье, выдавленное из теста. Занимает физическое место в оперативной памяти (RAM)
    `__init__` (Инициализатор): Метод (роддом объекта), который автоматически вызывается в момент создания и задает обязательные стартовые атрибуты
    `self`: Указатель на этот конкретный экземпляр в памяти. 

    2. 4 Столпа ООП:

        1. Инкапсуляция (Encapsulation)
        Объединение данных и методов работы с ними в отдельную "капсулу" (класс)
        Сокрытие внутреннего состояния: Защита данных от прямого вмешательства извне. Объект сам контролирует свои свойства через методы
        Обработка некорректных данных: Если передавать некорректное значение, метод должен перехватывать ошибку на входе, предотвращая повреждения данных в системе

        2. Наследование (Inheritance):
        Механизм создания ноаого класса на основе существующего без копирования кода (принцип DRY - Don't Repeat Yourself).
        Класс-наследник получает все методы и свойства родителя, но может добавлять свои уникальные.
        `super()` Вызов методов родительского класса, чтобы дилигировать базовую настройку отцу
        
        3. Полиморфизм (Polymorphism)
        Буквально: "Множество форм одного действия"
        Единый интерфейс у разных объектов с совершенно разной внутренней реализацией
        Позволяет обрабатыать разнородные объекты в одном цикле без бесконечных проверок `if / elif `
        Duck Typing (Утиная типизация в Python) Если крякает как утка - значит утка. Python не требует общего предка, главное, чтобы у всех физически присуствовал нужный метод

        4. Абстракция (Abstraction)
        Выделение чсущественных характеристик объекта и отсечение второстепенных.
        Абстрактный базовый класс (ABC): Класс-контракт из которого напрямую нельзя создать объект
        Через `@abstractmethod` на уровне архитектуры жестко фиксирует конракт: обязывает всех разработчиков реализовать конкретные методы в классах-наследниках под угрозой запрета запуска программы


14. Dunder методы в Python

    Dunder - это метод с двоийным подчеркиванием (`__name__`), которые перегружают стандартное поведение встроенных операторов и функций Python.

    1. Отображение объектов: `__str__` против `__repr__`
        `__str__` (Чек для покупателя):
        Пользовательский красивый вид: Вызывает функциями `print(obj)` и `str(obj)`.
        `__repr__` (Технический чертеж для разработчика):
        Точное, однозначное представление для отладки. Вызывается при отображении списков `[obj1, obj2]`, в логах и интерактивной консоли
        Золотое правило: `__repr__` должен выглядеть как валидный Python - код для воссоздания объекта: `"Orc(name="Digo", hp=100)"`
        Если `__str__` не объявлен, Python автоматически использует `__repr__`

    
    2. Truthy и Falsy в классах: `__bool__` и `__len__`

        По умолчанию любой созданный объект в Python всегда равен `True` (даже если у него 0HP)

        `__bool__(self)`: Метод, определяющий истинность объекта в условиях `if obj:`
        Пример для героя из тестового файла `return self.hp >` - жив(True), мертв(False)
        Позволяет писать лаконичный цикл `while obj and obj`:
        `__len__(self)`: (Запасной вариант):
        Если метода `__bool__` нет, Python ищет `__len__`
        Если `len > 0` объект считается `True`
        Если `len == 0` объект считается `False`
        Логика пустой корзины  `if not cart:`:
        1. Python вызывает `cart.__len__()` получает `0`
        2. Объект считывается как `False`
        3. оператор `not` инвертирует `not False` - `True`. Условие срабатывает!


    3. Сравнивание объектов `__eq__` (Оператор `==`)

        Поведение по умолчанию: Python сравнивает физические адреса в оперативной памяти (`id(obj1) == id(obj2)`), ведя себя как оператор `is`.
        Поэтому два объекта с абсолютно одинаковыми данными получат `False` (аналогия: люди близнецы - это разные личности).
        Метод `__eq__(self, other)`:
        Учит пайтон сравнивать объекты по содержимому (атрибутов)
        `self` - объект слева  от `==`, `other` - объект справа от `==`
        Применение в бэкенде: Проверка: Проверка `user_from_db == user_from_session` через сравнение `self.id == other.id`, даже если это разные сузности в RAM
